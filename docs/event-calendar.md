# 企业事件日历

Web 路由 `/events` 将告警子系统拥有的企业事件合同投影为只读日历。

## 生产入口

用户可通过以下入口打开日历：

- 研究侧边栏导航（**事件日历**）
- 研究概览卡片（**进入事件日历**）

直接访问 `/events` 仍然可用，但不再是唯一可达方式。

## 合同边界

- 日历调用 `GET /api/v1/alerts/triggers`，并传入
  `alert_type=corporate_event`。
- 日历不定义事件数据源、事件配置、缓存、回退策略或第二套事件 API。
- 日历不抓取行情或事件数据；data provider 治理仍由告警事件源负责。
- 影响与来源信息只展示告警触发记录公开的
  `impact_context` / `event_context` 投影。

因此，部署日历前必须先具备 PR #957 提供的事件告警合同。

## 加载行为

客户端按服务端允许的最大页大小持续读取，直到达到服务端返回的总数。
读取上限为 20 页（2,000 条）。如果后续页面失败或达到上限，页面会显示
本地化的“结果不完整”提示，不会把不完整范围误报为“没有事件”。

切换日期或刷新会取消上一个请求；请求代际保护会阻止旧响应覆盖新筛选条件。

## 范围

页面展示所选日期内已触发的企业事件，可显示影响摘要、自选/持仓标记、状态与来源。
它不实现未来事件 provider 目录，也不完整交付 issue #153 尚需的
agent bull/bear/watch 影响预览。


## 生产可达

事件日历页眉提供到企业事件告警视图（`/event-alerts`）的入口，无需手输 URL。`/events` 的研究导航入口由独立变更负责。

## 回滚

移除 `/events` 路由及其懒加载页面，或 revert 本变更。告警数据合同与事件评估链路不受影响。

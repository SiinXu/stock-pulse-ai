# 09 回測：用歷史建議校準信任，而不是賭下一筆


> 本頁為**繁體中文**操作手冊。產品介面亦可切換為繁體；若螢幕標籤與手冊不一致，**以介面為準**。

你好。回測頁想幫你回答的是：

> 過去一段時間，系統給出的 AI 建議，事後看起來是偏樂觀、偏保守，還是樣本太少啥也看不出來？

請先把預期放對：

- 這是 **對已經產生的建議做事後驗證**，不是完整量化回測 IDE。  
- 它 **沒有** 替你做複雜滑點、組合優化、實盤成交重放的承諾。  
- 樣本少時，任何漂亮百分比都可以先當故事看。

> ⚠️ 回測指標 **不構成** 未來收益承諾，也不是你的真實成交單。

---

## 怎麼進入

| 方式 | 路徑 |
| --- | --- |
| 導航 | **研究** → **回測** |
| 地址 | `/research/backtest` |
| 命令面板 | 搜「回測」 |
| 舊地址 | `/backtest` 一般會跳到規範路徑 |

可收藏參數示例：

`/research/backtest?code=600519&window=30&phase=all`

| 參數 | 含義 |
| --- | --- |
| `code` | 只看某一隻 |
| `window` | 回看天數（有上限，常見約 120，以界面為準） |
| `from` / `to` | 日期範圍 |
| `phase` | 盤前/盤中/盤後等階段過濾 |
| `page` | 分頁 |

---

## 什麼時候來，什麼時候先別來

| 場景 | 建議 |
| --- | --- |
| 已經用了幾周 | 選真實使用過的窗口再跑 |
| 剛裝好、幾乎沒報告 | 可以跳過；樣本爲 0 很正常 |
| 只關心一隻長線票 | 加 `code` 下鑽 |
| 和信號中心後驗一起看 | 中心偏單條生命周期；本頁偏批量事後統計 |

---

## 操作步驟

1. 進入回測頁。  
2. （可選）填代碼、窗口天數或日期、階段。  
3. 點運行 / 查詢。  
4. 先看 **樣本數**，再看方向準確率、勝率等。  
5. 無結果時讀頁面診斷（樣本不足、冷卻中、範圍太窄等），不要狂點。

---

## 指標怎麼讀才不傷身體

| 概念 | 人話 | 注意 |
| --- | --- | --- |
| 方向準確率 | 漲跌方向是否和建議同向 | 震蕩市會很難看或很偶然 |
| 勝率 | 有明確勝負時的比例 | **先看樣本數** |
| 模擬收益 | 按規則模擬的參考 | 沒算你的真實摩擦與情緒 |
| 止盈止損觸及 | 計劃價有沒有碰到過 | 沒寫計劃的信號參考弱 |
| 無法評估 | 太新、缺數據、冷卻中 | 正常桶，不是壞了 |

過新的記錄可能還在 **冷卻窗口**，暫時進不了統計——這是保護，不是系統偷懶。

---

## 和信號中心「再評估」的差別

| | 信號中心 review | 本回測頁 |
| --- | --- | --- |
| 入口 | `/signals?tab=review` | `/research/backtest` |
| 更適合 | Decision Signal 生命周期 / outcome 引擎 | 歷史建議批量事後表現 |

兩邊都是研究工具。設置裏的「回測 → 引擎」屬於更進階的開關。

---

## 使用案例

**案例 A：周末 15 分鐘**  
`window=30&phase=all` → 樣本是否大致夠看 → 若準確率亂跳，去信號中心看是不是大量 `watch` 或盤中階段 → 調整自己的使用習慣，而不是立刻換模型賭運氣。

**案例 B：單股信任校準**  
`code=600519&window=60` → 是否翻燒餅 → 結合報告歷史趨勢一起看。

**案例 C：剛裝好**  
空結果 → 正常。先去工作台積累報告，兩周後再來。

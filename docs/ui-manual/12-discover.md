# 12 发现（AlphaSift 选股）

## 页面入口与操作路径

| 方式 | 具体路径 |
| --- | --- |
| 主导航 | **研究** → **发现** |
| 命令面板 | 搜索「发现」「选股」「AlphaSift」 |
| 直链 | `/research/discover` |
| 旧路径 | `/screening` 会重定向到规范路径（以路由表为准） |
| 查询参数 | `market`、`strategy`、`count` 等（见下） |

页面标题常见为 **AlphaSift 选股**；导航文案为 **发现**。

「发现」用于在**全市场或策略约束下生成候选股票**，再交给分析工作台深挖。它是**实验性选股辅助**，不是保证收益的荐股黑箱。

> ⚠️ **实验功能与风险**  
> AlphaSift 选股仍处于实验阶段，结果仅用于研究与辅助判断，**不构成投资建议**；交易决策与损益由使用者承担。  
> 能力依赖：设置中启用相关能力、后端 AlphaSift 适配层与依赖可用。

## 适用场景

| 场景 | 建议做法 |
| --- | --- |
| 不知道今天看什么主题 | 先展开 **热点题材**，再挑 1～2 个概念股去分析 |
| 已有明确策略名 | 选择策略 → 设返回数量 → **运行选股** |
| 适配层未开 | 先点 **开启 AlphaSift**；失败则检查依赖 / 重建后端 |
| 候选出来后 | 对感兴趣代码点 **分析**，进入分析工作台，不要在发现页当完整报告读 |
| 新手 | 可先跳过本页，用自选 + 工作台跑通主链路 |

## 与其他模块的边界

| 模块 | 关系 |
| --- | --- |
| 分析工作台 | 发现产出**候选**；完整报告仍在工作台生成 |
| 大盘复盘 | 复盘讲市场温度；发现讲**可交易候选池** |
| 信号中心 | 选股本身不替代 Decision Signal；分析后才会沉淀信号 |
| 设置 → 数据源 / AlphaSift | 控制是否启用与相关 Key |

```mermaid
  D[发现: 策略/热点] --> C[候选列表]
  C --> A[分析工作台]
  A --> R[报告 / 信号]
```

## 页面结构

| 区域 | 作用 | 小白怎么记 |
| --- | --- | --- |
| 启用状态 | 选股已开启 / 未开启 / 适配层不可用 | 「开关与健康检查」 |
| 风险提示 | 实验声明 | 每次使用前扫一眼 |
| **热点题材** | 题材热度、阶段、发酵路线、概念股（默认可折叠） | 「今天市场在炒什么线索」 |
| **策略选择** | AlphaSift 策略列表或自定义参数 | 「用哪套尺子筛」 |
| **参数** | 市场、策略参数、返回数量（1～100） | 「筛多少只要几只」 |
| **运行选股** | 提交异步任务并轮询状态 | 「开始筛」 |
| **候选结果** | 摘要、因子、风险、可点分析 | 「短名单」 |

## 操作步骤

### A. 首次启用

1. 进入 **研究 → 发现**。  
2. 若显示 **AlphaSift 未开启**，点击 **开启 AlphaSift**。  
3. 若 **适配层不可用**：确认后端依赖已安装并重启服务（桌面端可能需更新/重装；开发环境见完整指南）。  
4. 启用成功后再做热点或选股。

### B. 用热点题材找线索

1. 展开 **热点题材**（默认可能折叠以省流量）。  
2. 需要最新数据时点 **刷新热点题材**（会拉排行、热度、生命周期、活跃龙头等）。  
3. 点击某一题材，加载发酵路线与概念股。  
4. 对概念股点 **分析 {代码}** → 进入分析工作台。  
5. 注意 **缓存回退 / 降级 / 缺失字段** 提示，降级时热度仅作弱线索。

### C. 按策略运行选股

1. **选择策略**（列表来自 AlphaSift；加载失败时可尝试手动参数）。  
2. 设置 **市场**（如 A 股 `cn`）、**返回数量**（1～100 的整数）。  
3. 点击 **运行选股**。  
4. 等待任务：提交中 → 运行中 → 完成；轮询超时/网络抖动时界面可能自动重试。  
5. 阅读候选摘要、因子与风险；需要时再点分析。  
6. 若提示 **LLM 重排失败并回退本地因子评分**：仍可看列表，但排序解释力下降。

### 可收藏 URL 示例

| URL | 含义 |
| --- | --- |
| `/research/discover` | 默认发现页 |
| `/research/discover?market=cn&strategy=dual_low&count=3` | 指定市场、策略、数量（以当前默认/合法值为准） |

参数非法时页面会回落到安全默认（实现中常见默认：`market=cn`、策略如 `dual_low`、`count=3`）。

## 术语表

| 术语 | 解释 |
| --- | --- |
| **发现 / Discover** | 导航名；页面能力为 AlphaSift 选股 |
| **AlphaSift** | 内置选股适配层 / 实验能力品牌名 |
| **策略（strategy）** | 一套筛选与评分规则 ID 或参数包 |
| **热点题材（hotspot）** | 主题热度与生命周期线索 |
| **发酵路线** | 题材从萌芽到扩散的时间线叙述 |
| **候选（candidate）** | 策略输出的短名单条目 |
| **本地因子评分** | 不依赖 LLM 重排时的量化打分回退 |
| **theme_heat** | 部分策略会把题材热度纳入评分 |
| **返回数量 count** | 本次最多展示/返回的候选个数 |

## 建议配置

| 项目 | 新手建议 |
| --- | --- |
| 是否必用 | **否**；先跑通工作台再玩发现 |
| 返回数量 | 3～10，避免一次筛太多看不过来 |
| 热点刷新 | 不要高频狂点刷新（可能触发限流） |
| 下一步 | 候选只作线索 → 工作台出报告 → 再谈信号/持仓 |

## 使用案例

**案例 A：主题投资线索**  
1. 刷新热点 → 选一个你理解的行业题材。  
2. 从概念股里挑 2 只点分析。  
3. 用 [08 阅读报告](08-reading-reports.md) 看风险，而不是只看热度分。

**案例 B：策略试跑**  
1. 选一个默认策略，`count=5`，市场 A 股。  
2. 运行选股，等完成。  
3. 若 LLM 重排回退，仍阅读因子与风险字段。  
4. 对第一名候选跑工作台报告，决定是否加入自选。

**案例 C：开启失败**  
1. 提示适配层不可用或开启失败。  
2. 检查：后端是否启动、AlphaSift 依赖是否安装、设置中实验开关。  
3. 仍失败：暂用自选股路径，不要卡住整个上手流程。

**案例 D：任务卡住**  
界面提示轮询超时但任务仍在后台 → 稍等自动重试；长期无结果再重新提交，并查看是否缺 LLM Key、限流或数据源不可用。

## 常见提示怎么读

| 提示方向 | 含义 |
| --- | --- |
| 缺少可用 LLM API Key | 选股链路需要模型，先配 [10 设置](10-settings.md) |
| 请求过于频繁 | 降低刷新/提交频率 |
| 数据源降级 | 结果可用但质量下降 |
| 交易日历暂无开市日 | 非交易时段或日历数据问题，结论更保守 |
| 暂无缓存热点 | 展开后点刷新拉取 |

# 自选股分组

自选股分组用于在 Web 首页按主题或策略组织 `STOCK_LIST` 中的标的。一个标的可以属于多个分组，但分组不会改变分析、告警、CLI 或定时任务读取的全局自选股集合。

## 数据与身份合同

- `STOCK_LIST` 是唯一的成员资格权威来源。分组表只保存权威标的的分组归属、组内顺序和只读计算属性。
- 所有入口使用同一个市场感知身份规则。`00700.HK`、`HK00700` 和 `00700` 会收敛为同一个 `HK00700` 成员。
- 每次读取分组前都会在一个数据库事务内执行对账：删除已离开 `STOCK_LIST` 的幽灵成员、去重别名、补入缺失成员，并修复连续排序。新增成员时先提交 `STOCK_LIST`，再写分组；若后者失败，下一次读取会把成员恢复到默认分组并保留可见错误。
- 默认分组使用保留键 `default`。数据库不保存用户语言文案，Web 通过稳定的 `watchlist.defaultGroupName` key 本地化显示。

## 并发与边界

分组响应包含单调递增的 `revision`。每个修改请求必须传 `expected_revision`；旧 revision 返回 `409 watchlist_group_revision_conflict`，客户端随后重新读取服务端状态。重排请求必须恰好包含当前全部且不重复的组 ID 或成员代码，否则返回 `400`。

默认上限为 50 个分组、每组 500 个成员、总计 2,000 条分组成员关系。组名最多 80 个字符。计算属性是版本化、只读的 schema：`schema_version=1`，可选有限数值 `ai_score`（0–100）和可选布尔值 `focus`；客户端不能写任意 JSON。

## 交互与无障碍

桌面端拖拽只从可见拖拽手柄启动，手柄也支持上下方向键排序。移动端 DOM 不启用拖拽，提供明确的上移、下移和“移动到分组”操作。菜单支持 Escape、外部点击、焦点返回和屏幕阅读器实时提示。

## 升级、备份与恢复

升级会创建 `watchlist_groups`、`watchlist_group_members` 和 `watchlist_group_state`。首次读取自动创建默认分组并导入现有 `STOCK_LIST`，不会要求手动迁移。升级前应备份应用数据库和 `.env`/系统配置中的 `STOCK_LIST`。

运行时若怀疑双写中断，只需确认 `STOCK_LIST` 正确并重新读取分组 API；事务对账会恢复成员集合和排序不变量。日志中的 `watchlist_group_internal_error` 保留诊断信息，公开 500 响应不会暴露数据库路径或驱动错误。

## 回滚

回滚代码后旧版本会忽略新增表。执行 migration downgrade 会删除三个分组表，并永久丢失分组名称、排序和计算属性；该操作不可恢复，必须先备份数据库。`STOCK_LIST` 不会被 downgrade 修改，因此全局自选股仍可使用。
